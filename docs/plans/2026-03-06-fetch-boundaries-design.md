# fetch 边界行为设计

## 目标
- 为 `fetch` 增加重定向、`gzip`、`deflate`、非 HTML 响应的集成测试。
- 若测试暴露真实问题，则按最小改动修复。

## 方案
1. 只写单元测试
   - 快，但对真实网络行为覆盖不足
2. 使用 `httptest` 做集成测试（推荐）
   - 最贴近当前实现，覆盖 HTTP 客户端真实行为
3. 做更重的端到端测试
   - 成本过高，不适合当前仓库规模

## 预期行为
- `fetch` 遇到 3xx 时，返回最终响应内容，并以最终 URL 作为 `Response.URL`
- `fetch` 能处理 `gzip` 和 `deflate` 编码的 HTML 响应
- `fetch` 处理非 HTML 响应时，不应错误提取标题，正文应尽量保真

## 风险控制
- 优先补测试，再做最小实现
- 改动限制在 `pkg/http.go` 与测试文件
