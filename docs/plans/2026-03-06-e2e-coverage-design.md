# CLI 端到端覆盖扩展设计

## 背景

当前已经有一条本地模拟 Web 的 CLI 端到端测试，能够证明最基本的扫描主链路可用。但它还不足以覆盖命令行常用参数路径和不同指纹识别方式。

## 目标

- 继续使用本地 `httptest` 服务，不依赖外网
- 覆盖 CLI 主要运行路径：`-u`、`-l`、`-o`、`-j`、`-s`
- 覆盖主要指纹识别方式：`body`、`header`、`title`、`faviconhash`、`ARL`
- 确认命令执行无错误、输出结构可用、识别结果真实有效

## 方案

采用多条小型 CLI 端到端测试，而不是一条超级大测试：

1. 每条测试启动一个本地 `httptest` 服务
2. 通过子进程调用 `Execute()`，模拟真实命令行运行
3. 使用临时 EHole / ARL 指纹文件驱动识别结果
4. 针对不同参数路径分别断言标准输出、静默输出或输出文件内容

## 覆盖矩阵

### 命令路径

- `-u` 单目标扫描
- `-l` 文件列表输入
- `-o` JSON 文件输出
- `-j` JSON 终端输出
- `-s` 静默模式

### 指纹路径

- EHole `body` 关键词
- EHole `header` 关键词
- EHole `title` 关键词
- EHole `faviconhash`
- ARL `body` / `header`

## 风险控制

- 不修改业务逻辑，只补测试
- 使用显式 `tcp4 127.0.0.1:0` 监听，减少 IPv6/沙箱差异
- 测试之间不共享全局命令状态，避免 Cobra 全局 flag 污染
