# Meta Refresh 跳转提取设计

## 背景

当前 `pkg/jsjump.go` 使用正则 `<meta.*?http-equiv=.*?refresh.*?url=(.*?)>` 直接从整段标签中提取跳转目标。面对真实页面里常见的自闭合写法，如 `<meta http-equiv="refresh" content="0;url=http://example.com" />`，捕获结果会把结尾的 `" /` 一并带入，导致后续 `url.Parse` 接收到脏值，最终额外入队并扫描错误的 URL。

## 目标

- 保留现有“跟随 `meta refresh` 跳转继续扫描”的能力
- 修复自闭合标签、带引号 URL、大小写混用等场景下的脏 URL 提取问题
- 不改变 `window.location.href` 与 `redirectUrl` 的既有行为
- 通过回归测试锁定该缺陷

## 方案对比

### 方案 A：解析 `content` 属性后再提取 `url=`（推荐）

先定位候选 `meta` 标签，再从标签属性中取 `content` 值，最后仅在 `content` 内解析 `url=`。这样可以避免把标签闭合符带入 URL，同时保留绝对 URL 与相对 URL 两类跳转。

优点：
- 直接修复根因，而不是事后清洗脏字符串
- 比单纯补正则更稳，能覆盖属性顺序变化和大小写混用
- 保留当前“继续跟随跳转”的设计目标

代价：
- 需要增加少量属性解析辅助逻辑

### 方案 B：保留现有正则并追加清洗

继续使用现有正则，匹配后再移除 `" /`、`/>` 等尾巴。

优点：
- 改动最小

缺点：
- 只是在修补症状，后续遇到别的 HTML 变体仍容易出错
- 规则会越来越碎，维护成本高

### 方案 C：忽略绝对 URL 的 `meta refresh`

像 EHole 一样直接跳过包含 `http` 的跳转目标。

优点：
- 可以规避本次问题现象

缺点：
- 会丢失真实且常见的绝对跳转能力
- 本质上不是修复，而是降低功能覆盖

## 设计

采用方案 A。

1. 保留现有 JS 跳转提取路径，仅将 `meta refresh` 提取从“整段标签抓取”改为“属性级解析”
2. 新增 `meta` 标签属性提取辅助逻辑，用于读取 `http-equiv` 与 `content`
3. 新增 `content` 字段解析逻辑，仅从 `content` 中读取 `url=` 右侧值
4. 继续使用现有 `url.Parse` 与 `ResolveReference` 完成绝对/相对路径归一化
5. 补充针对自闭合 `meta refresh` 绝对 URL、带引号绝对 URL 的回归测试

## 测试策略

- 在 `pkg/jsjump_test.go` 中新增失败用例，覆盖自闭合标签 + 绝对 URL
- 补充大小写混用 + 单引号包裹绝对 URL 的回归测试
- 先运行失败用例确认旧实现失败
- 完成实现后重新运行 `pkg/jsjump_test.go` 与相关 `pkg` 测试，确认回归通过
