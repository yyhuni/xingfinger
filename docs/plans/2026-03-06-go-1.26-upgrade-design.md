# Go 1.26 升级设计

## 背景

项目当前在 `go.mod` 中声明 `go 1.15`，而本次目标是把项目最低支持版本正式提升到 Go 1.26，并确保核心扫描功能在升级后保持正常。

根据 Go 官方文档：
- Go 1.26.0 已于 2026-02-10 发布。
- 从 Go 1.21 开始，`go` 命令支持按 `go.mod` 中的 `go` / `toolchain` 声明自动切换或下载更新的工具链。
- `go get go@<version>` 可用于更新模块的 Go 工具链依赖。

## 目标

- 将项目最低支持 Go 版本正式提升到 1.26
- 保持现有业务功能与扫描语义不变
- 完成工具链升级后的依赖整理与全量验证
- 增加一条本地模拟 Web 的端到端扫描验证链路

## 方案选择

采用“标准升级 + 本地功能验证”的方案：

1. 更新 `go.mod` 的 Go 版本到 1.26
2. 允许 Go 工具按标准机制选择/下载 1.26 工具链
3. 更新 `README.md` 中的版本说明
4. 在 Go 1.26 下执行 `go mod tidy`、`go test ./...`、`go build ./...`、`go vet ./...`
5. 追加本地模拟 Web 扫描验证，确认 CLI 主路径可正常工作

## 风险与控制

### 风险 1：工具链下载或切换失败

通过显式使用 `GOTOOLCHAIN=go1.26.0` 进行验证；若下载受限，则按需要申请放开执行。

### 风险 2：依赖在新工具链下暴露兼容性问题

只修复工具链兼容问题，不顺带做业务逻辑变更。

### 风险 3：升级只停留在声明层，未验证真实功能

增加本地模拟站点的扫描测试与 CLI 级回归验证，确保不只是单元测试通过。

## 预期影响

- 开发/构建基线提升到 Go 1.26
- `go.mod` / `go.sum` 可能出现规范化变化
- 业务功能预期不变，性能与工具链行为可能随新版本运行时略有改善
