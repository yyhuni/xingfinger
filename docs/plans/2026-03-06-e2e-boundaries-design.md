# CLI 端到端边界覆盖设计

## 背景

当前 CLI 端到端测试已经覆盖了基础命令路径与主要指纹识别路径，但仍缺少一些更接近真实网络环境的边界场景：HTTPS、自带重定向、压缩响应体以及代理请求路径。

## 目标

- 使用本地模拟服务继续扩展真实 CLI 扫描验证
- 覆盖 HTTPS 自签名证书场景
- 覆盖 HTTP 302 跳转与 JS 跳转场景
- 覆盖 `Content-Encoding: gzip/deflate` 的响应体处理
- 覆盖 `-p/--proxy` 代理请求路径
- 保持不修改业务逻辑，只补测试

## 方案

继续沿用 `cmd/root_e2e_test.go` 中的子进程 CLI 调用方式：

1. 新增本地 TLS 测试服务辅助函数
2. 通过小型独立测试覆盖每一种边界场景
3. 使用现有 EHole 指纹与结果文件断言真实输出
4. 对代理路径增加本地 HTTP 代理转发验证

## 覆盖项

- HTTPS 自签名 + body 指纹命中
- HTTP 302 跳转后最终 URL 与指纹命中
- JS redirect 继续入队扫描并命中跳转页
- deflate 响应解压后标题与指纹命中
- gzip 响应解压后标题与指纹命中
- 代理转发扫描成功且请求确实经过代理

## 风险控制

- 仍使用 `tcp4 127.0.0.1:0` 显式监听
- 只增加测试和文档，不改业务逻辑
- 若测试暴露真实缺陷，再单独向用户确认是否允许改逻辑
